# Phase 1 実装とPR計画

**到達点**。保存済み入力の再生と、承認対象1ページの単発収集を同じ観測契約で比較できる。対象が保留の場合もCIで収集処理と欠測処理を証明し、パイロット台帳に理由を残せる。

## PR 1　オフライン観測契約とCI

- **ブランチ案** `phase-1/replay-contract`。このリポジトリの初期コミットを土台に、Pythonの対応版でテストが走るGitHub Actions、Draft 2020-12のJSON Schema検証、インストール済み `tao` のCLIテストを追加する。ネット接続を必要とするパッケージ準備と、テスト実行時の対象サイトへの接続を分ける。
- **受け入れテスト**。同じ入力とプロデューサー版で期待JSONとバイト一致。完全HTMLの宣言あり／なし、明示タグの省略、非HTML、本文の途中打ち切り、ブロック、未取得、入力の重複キー・不正URL・サイズ上限を検証。ネットワークを遮断した環境で再生し、出力にHTML本文を含めないことを確認する。
- **完了条件**。CI緑、JSON Schemaと期待出力の一致、開発者がREADMEの手順で再現可能。初期コミットにCLI・合成フィクスチャ・オフラインテストが含まれる。

## PR 2　許可済み公開面の単発収集

- **ブランチ案** `phase-1/public-capture`。 `tao capture TARGET_ID --manifest PATH --out PATH` を追加。URLはレビュー済み台帳の完全一致した公開ページから解決し、利用条件と保存の判断を審査日付きで記録する。収集設計は、識別できるエージェント、単一並列、同一ホストの事前承認済み経路だけを対象とする最大2回のリダイレクト、応答時間・本文サイズの上限、`robots.txt` の判定を備える。接続を拒否された場合や条件が不明な場合はそこで停止し、理由をメタデータに残す。収集プロファイルには実行環境、地域、言語、時刻、HTTP設定を記録する。
- **範囲**。通常の未ログイン公開HTMLの取得のみ。フォーム操作、予約、ログイン、クエリ生成、ページの探査、JS実行、資産の追跡、認証方式の実証試験、脆弱性検査は対象外。テストの通信先はローカルの自作サーバーまたはモックのみに固定する。
- **受け入れテスト**。未承認IDとrobots拒否時の対象リクエストが0件。承認外の転送先に接続しない。承認済み転送は上限内で成功。403・429・障害・途中打ち切り・HTML以外の応答が規定の欠測状態になる。Cookie、クエリ・フラグメント、資格情報が保存や標準出力に入らない。中間画面の分類が未確定の場合は有効観測として採用しない。
- **完了条件**。自作サーバーで `capture → replay` が成功し、承認済みのパイロット対象があれば1件の手動動作確認を記録。取得・保存を承認できない対象は保留を記録し、実測として公開しない。

## PR 3　観測の評価とデータ書き出し

- **ブランチ案** `phase-1/evaluate-and-export`。評価基準の最初の1項目を実装する `tao evaluate OBSERVATION --rubric-version VERSION` と、レビューした観測・評価をまとめるJSONL書き出しを追加する。ルール版の固定と、出典および欠測の追跡を優先する。
- **受け入れテスト**。4つの評価状態、未知の版、壊れた証拠参照を検証。確度版または評価版だけを変えたときに同じ観測IDを参照し、旧評価を保持することを確認。欠測が比較表の分母と状態表示に反映され、原資料や公開対象外データが出力されないことを検証。
- **完了条件**。合成データで `capture → replay → evaluate → JSONL` の一連の流れを再現できる。ダッシュボードと定期観測はロードマップの後続段階で開始する。
