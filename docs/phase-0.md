# Phase 0 研究設計

## 調査の問い

TAOは、組織が技術を採用・維持・廃止する判断と、その判断が将来の変更コストや提供できる価値に与える影響を調べる。公開Webから始め、利用者に見える技術の選択を同じ手法で繰り返し観測する。ページの公開日やライブラリの世代は経緯の記録に使う。評価には、用途、信頼性、相互運用性、変更のしやすさ、移行負担といった条件を使う。静的HTMLの継続利用や保守済みの旧版も、その条件に合えば合理的な選択となる。

| 概念 | 問いと必要な証拠 |
| --- | --- |
| 技術適応能力 | 要件や標準が変化したとき、適切な対応がどのくらいの期間で観測されるか。同じ公開面を定点観測し、変更前後の観測日で区間を示す。公開面から判断できるのは変化の時期と現れ方まで。 |
| 工学的合理性 | 維持・部分更新・置換のどれが、比較対象の用途に必要な品質と制約を満たすか。比較可能な公開面、標準仕様、公開設計資料、運用実績が必要。 |
| 経済的合理性 | 移行費を含めた総費用と、余力や新機能による便益が時間とともにどう変わるか。測定期間・費用負担者・前提を明記し、推計と開示実績を明示する。 |
| 人的補完の罠と隠れた費用 | 手作業、引き継ぎ、入力の二重化、利用者の待ち時間や問い合わせが運用を支えているか。更新の圧力を弱めるかは仮説。業務フローや工数の開示など、独立した資料が必要。 |
| エコシステムと能力の蓄積 | 外部の保守、標準、ツールの進化を取り込めるか。再利用や学習による将来の変更費低下と、乗り換え・ベンダーロックインの費用を追う。 |
| 機会費用 | 維持を選んだ場合の機能、分析、顧客体験などの機会損失を比較する。将来の便益は前提付きのシナリオとして扱う。 |
| ベンダー帰属 | 発注、要件決定、実装、ホスティング・基盤供給、運用保守の役割を特定の公開面と時期に結び付けて記録する。製品の観測と、開発・運用主体に関する主張には、それぞれの根拠を求める。 |

「神Excel」は、現場が手順と知識を積み上げて業務を成立させているという研究仮説の例。CRMの導入・社内作業・現場の負担は、公開ホームページの観測対象外とする。日米差は後続研究の問いとして登録し、業種、用途、企業規模、規制、委託形態などを揃えた追加資料がある場合に検討する。IPAの日米独調査は仮説を設計する背景資料、無形資産と生産性の研究は投資効果の時間差を考える背景資料に使う。 [IPA「DX動向2025」](https://www.ipa.go.jp/digital/dx-trend/dx-trend-2025.html) · [Brynjolfsson, Rock & Syverson, The Productivity J-Curve](https://www.aeaweb.org/articles?id=10.1257/mac.20180386) · [RIETIの国際比較](https://www.rieti.go.jp/en/publications/summary/24120002.html)

### 後続の経済分析と帰属の記録

- 同じサービス要件に対し、維持、部分更新、置換を3年・5年で比較する。移行、一時並行運用、教育、ライセンス、保守、手作業、利用者の時間、停止・障害の期待損失、撤退費用と追加便益を項目化する。通貨・割引率・低位／基準／高位の見積りと、どの条件で結論が逆転するかを明示する。実測値、開示値、推定値、未知を記録し、便益や機会費用の重複計上を避ける。
- ベンダーの主張は `surface_id, vendor, role, valid_period, source, supporting_evidence, confidence, reviewed_at` を持つ独立レコードとする。一次資料が公開面・期間・役割を明示した場合に帰属を検討し、顧客側とベンダー側の資料が同一発表に依存する場合は一つの根拠として数える。資産URLや製品識別子は調査の手掛かりとして扱う。矛盾は両論と理由を保持し、訂正履歴と差し替え先を記録する。

## パイロット設計

ANAとJALの日本向け消費者ホームページを最初の対にする。米国側はDeltaとAmerican Airlinesの米国向け消費者ホームを候補にし、一社固有の実装を市場全体の特徴と取り違えるリスクを抑える。4社は探索的な事例比較の範囲とし、国別の傾向は別の標本で検証する。比較の単位は `target_id × surface × capture_profile × time`。会社集計の前に、ホーム・予約入口・会員案内は機能の違いを記録し、観測承認後に同じ用途どうしを比較する。認証情報は公式の公開説明に限る。予約操作やログインで観測範囲を広げない。 [候補台帳](../pilot/airlines-v0.2.0.json)

初回は単発で、実測フェーズでは独立した二つの観測日に同じ対象を確認する。言語・観測地域・エージェント・実行条件をそろえ、地域分岐、同意画面、障害、キャッシュ差を注記する。比較の分母は対象数と有効観測数の両方を記載し、欠測件数・理由を表示する。変化の再確認では更新の幅や適用範囲、同じ期間に起きた他の変更も記録する。 [観測仕様](methodology.md)

Phase 0の成果物でPhase 1の実装に着手できる。実サイト観測の可否、パイロットの実測値、コード／データの公開ライセンスと掲載範囲は、各段階の判断として保留する。
